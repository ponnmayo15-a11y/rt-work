# rt-work

診療放射線技師の仕事まわり（CT認定更新、技師会・研究会の情報）

## CT認定技師 単位講習会リサーチ(Webアプリ版)

X線CT認定技師の更新（5年で30単位）に使える講習会を毎週自動でリサーチし、
GitHub Pages上のWebアプリで一覧できる仕組みです。**Google Sheetsは使いません**。
データは全てこのリポジトリ内のSQLite(`data/ct_credit.db`)で管理し、表示用に
`docs/data.json`へ書き出したものをGitHub Pagesが配信します。

### 仕組みの概要

1. 日本X線CT専門技師認定機構の「[単位認定講習会等一覧](https://www.ct-ninteikikou.jp/nintei/tani_nintei_list/)」
   を毎週チェックし、前回チェック以降に新しく追加された回・まだ開催日を迎えていない回だけを対象にする。
2. 各回の詳細PDF（チラシ）を取得し、開催形式（オンライン/オフライン）・開催都道府県・参加費を自動で読み取る。
3. 以下の条件で判定する。
   - タイトルに「学術大会」「学術集会」「臨床大会」「総会」「全国大会」を含む
     → 技師会・技術学会の大きな学会とみなし、他の条件を問わず採用
   - オンライン開催 かつ 参加費が上限以内 → 採用
   - オフライン開催 かつ 対象都道府県 かつ 休日開催（地元県のみ平日18時以降開催も可）→ 採用
   - 上記以外で、判定に必要な情報が欠けているものは「要確認」として掲載（見落とし防止のため）
4. 採用/要確認の講習会・単位種別ごとの公式ポイント数(平成25年4月改訂の機構基準表による)を
   `data/ct_credit.db`に書き込み、表示用の`docs/data.json`を再生成する。

### Webアプリ(GitHub Pages)

`docs/index.html`が本体です。リポジトリの `Settings > Pages` で
`Deploy from a branch` → このブランチ(または `main`) の `/docs` フォルダを指定すると、
`https://ponnmayo15-a11y.github.io/rt-work/` のようなURLで公開されます(未設定の場合は下記「初回セットアップ」参照)。

表示内容:

- **概要**: 合計ポイント数・認定期間満了日までの残り日数・単位取得目安日(満了の1年前)までの残り日数
- **対象講習会リスト** / **要確認**: 開催日が近い順の一覧。各回に「参加予定にする」ボタン
- **参加予定**: 「参加予定にする」を押した講習会だけの一覧。各回に「参加した」ボタン
- **参加履歴**: 実際に参加した講習会の記録(講習会名・開催日・単位種別・ポイント数)
- **設定**: 条件のチューニング項目を表示・変更リクエストできる

#### 行くつもりの講習会を管理する(参加予定 → 参加した)

1. 「対象講習会リスト」や「要確認」で、行くつもりの講習会の「参加予定にする」を押す
   → その講習会が「参加予定」タブに一覧される(元のリストにも「予定としてマーク済み」と表示される)
2. 実際に参加したら、「参加予定」タブでその講習会の「参加した」を押す
   → カレンダー登録・参加履歴への記録が行われ、「参加予定」タブからは消える

「参加した」は「参加予定」タブにしかありません(対象講習会リスト等から直接「参加した」にはできません)。

#### ボタンを押すと起きること

書き込み(参加予定・参加登録・設定変更)には常時稼働のサーバーを使わず、**GitHub Issueをきっかけに
GitHub Actionsが実行される**方式にしています(常時起動のプログラムは不要)。

1. ボタンを押すと、GitHubの新規Issue作成画面が開く(内容は自動入力済み)
2. GitHubにログインした状態でそのまま「Submit new issue」を押す(1クリック)
3. `.github/workflows/handle_issue.yml` がIssue作成を検知し、`scripts/handle_issue.py` を実行して
   - `data/ct_credit.db` の該当講習会を参加予定/参加済みにする、または設定を更新する
   - 「参加した」の場合のみ: Googleカレンダーにその予定を登録し(重複がないか検索してから作成)、
     「参加履歴」に記録を追記する
   - `docs/data.json` を再生成してコミット・push(数分でPagesに反映される)
4. 処理が終わるとIssueに結果がコメントされ、自動でクローズされる

「設定変更をリクエスト」ボタンも同じ仕組みで、変更したい項目だけをIssue本文に含めて投稿すると
次回の週次リサーチから新しい条件が適用されます(参加費上限の変更はその場でも再判定され、
対象外になった既存の講習会が対象講習会リストから削除されます)。

### 自動実行（週次リサーチ）

`.github/workflows/weekly_ct_credit_research.yml` により、毎週月曜7:30 JSTに自動実行されます。
`Actions` タブから手動実行（workflow_dispatch）も可能です。

**重要**: GitHub Actionsのスケジュール実行はデフォルトブランチ（`main`）にあるワークフローだけが
対象になります。このブランチが `main` にマージされるまでは、週次の自動実行は始まりません。

### 初回セットアップ

1. **GitHub Secretsの登録**: `Settings > Secrets and variables > Actions` で以下を登録
   - `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REFRESH_TOKEN`
     (Google Sheets APIの読み書きに使っていたものと同じでよいが、**Googleカレンダーへの書き込みには
     `https://www.googleapis.com/auth/calendar` スコープが追加で必要**。無い場合、参加登録自体は
     成功するがカレンダー登録だけ失敗する(Issueへのコメントでエラー内容が分かる))
   - `CT_CALENDAR_ID` (任意): カレンダーIDを指定しない場合、リフレッシュトークンの持ち主自身の
     プライマリカレンダーに登録される。技師会の共有カレンダーなど別のカレンダーに登録したい場合は
     そのカレンダーIDを設定する
2. **GitHub Pagesの有効化**: `Settings > Pages` で `Source: Deploy from a branch` を選び、
   ブランチとフォルダ(`/docs`)を指定する
3. このブランチを `main` にマージすると、週次自動実行とPagesの本番URLが有効になる

### 手動実行

```bash
pip install -r requirements.txt
export GOOGLE_CLIENT_ID=...
export GOOGLE_CLIENT_SECRET=...
export GOOGLE_REFRESH_TOKEN=...
python -m ct_credit_research.main
```

`data/ct_credit.db` が更新され、`docs/data.json` が再生成されます。

### データベース構成(`data/ct_credit.db`)

- `courses`: 講習会1件ごとの情報(認定No・日時・単位種別・ポイント数・開催形式・参加費・判定理由など)。
  `list_type` が `main`(対象講習会リスト) / `manual`(要確認) を区別し、`attended` が参加チェックにあたる
- `settings`: 条件のチューニング値(未設定のキーは`config/settings.yaml`のデフォルト値を使う)
- `history`: 参加履歴(講習会名・開催日・単位種別・ポイント数)
- `run_log`: 実行ログ(実行日時・新規確認件数・追加件数など)
- `processed_nos` / `meta`: 処理済みの認定No・最終処理Noの記録(取りこぼし防止・再スキャン防止用)

### 設定のカスタマイズ

#### Webアプリの「設定」タブで変更する（コード不要）

値を変更して「設定変更をリクエスト」を押すとGitHub Issueが作られ、投稿すると自動で反映されます。

- オンライン参加費上限(円) / 対象都道府県(オフライン) / 地元県(平日夜も可) / 平日夜の開始時刻(HH:MM) /
  大きな学会キーワード
- 単位種別・所要区分・開催形式・曜日の絞り込みフィルタ(空欄なら制限なし。**大きな学会には適用されません**)

#### config/settings.yaml で変更する

上記以外（都道府県判定用のキーワード辞書、オンライン判定キーワード、無料判定キーワード、
出典URLなど、より技術的な設定）は `config/settings.yaml` を編集してコミットしてください。

- 更新期限が近づいたら `renewal_period_end` を次回の期限に書き換えてください（5年ごとの手動更新が必要）

### 既知の制約

- 開催地・参加費はチラシPDFの全文からキーワードで自動推定しています。「対象講習会リスト」に載った回でも、
  特に開催地については詳細PDFで一度確認することをおすすめします。
- 参加費は複数の金額が書かれている場合、自動判定では最も安い金額を採用します。
- 「ポイント数」は機構の公式基準表からの自動計算であり、各講習会のチラシに書かれている単位数
  （申請中で確定していないことがある）とは一致しない場合があります。基準表の方を優先しています。
- 「参加した」ボタンを押した後、GitHubへの投稿(1クリック)が必要です。投稿してから
  カレンダー登録・一覧への反映まで数分かかります。
- カレンダー登録には `GOOGLE_REFRESH_TOKEN` にCalendarスコープが必要です(初回セットアップ参照)。
  無い場合、参加登録自体は成功しますがカレンダー登録は失敗し、Issueのコメントでその旨が分かります。
- これまでに参加済み（この仕組みが動く前に参加したもの）の講習会を追加したい場合は、
  Claudeに伝えて `data/ct_credit.db` の `history` テーブルに直接追記してもらってください。

### 過去の構成(Google Sheets版)について

以前はGoogle Sheetsにデータを書き込む方式でした。`ct_credit_research/sheets_client.py` /
`config_sheet.py` は、当時のスプレッドシートから今回のSQLiteへ移行するための
`scripts/migrate_from_sheets.py` が使うためだけに残しています(通常運用では使いません)。
